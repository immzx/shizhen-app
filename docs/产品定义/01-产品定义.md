# 拾帧 · 产品定义（精简版 PRD）

> 版本 v0.1 ｜ 2026-09-04 ｜ 状态：待评审
> 本文是后续所有设计决策的判断依据。任何新增需求，先回到「产品原则」检验是否成立。

---

## 一、一句话价值主张

**从几千张照片里，挑出真正值得留下的那十几帧，做成一本你愿意拿在手里的作品集。**

- 对用户说的版本：「帮你把一堆照片，变成一组作品。」
- 内部判断标准：如果一个功能不能让「留下来的照片更值得留下」，就不做。

## 二、用户与场景

### 2.1 目标用户

| 层级 | 人群 | 特征 |
|---|---|---|
| 核心 | 25–35 岁、有持续拍照习惯的城市用户，女性占比预计偏高 | 相册 5000+ 张、几乎从不整理、手机里躺着「拍得其实还行」的自我认同，但从未兑现 |
| 次要 | 亲子记录者、旅行爱好者、胶片/复古摄影爱好者 | 有明确的「成册」诉求，打印意愿显著高于均值 |
| 长尾 | 摄影入门者 | 需要精选与呈现的范式，缺乏排版能力 |

### 2.2 典型场景

1. **旅行归来**：一次拍了 800 张，发朋友圈选不出九张 → 拾帧筛出 15 张，生成作品集直接发。
2. **成长记录**：孩子一周岁，几百张照片散落各处 → 按月/按主题筛选并成册，打印留存。
3. **年度回顾**：年底整理一整年 → 以「时间」为线索的批量筛选。
4. **摄影输出**：拍完一组主题片 → 快速精选出片，用于发布或投稿。

### 2.3 真正的痛点（关键判断）

用户的痛点**不是「不会整理」，而是「不舍得删」**。

- 整理照片的技术门槛很低，真正的障碍是**决策的心理成本**：每一张都承载着一段记忆，删除等于否定。
- 因此拾帧的本质不是「相册管理工具」，而是**一套降低决策成本的游戏化机制**：
  - 把「要不要删」（否定式、有损失感）改写为「留不留」（选择式、有获得感）；
  - 把「逐一判断」改写为「直觉快速反应」，用速度绕开心理纠结；
  - 用「留下 N 张」的正向计数替代「删掉 N 张」的负向计数。

> 这条决定了：**筛选环节的核心 KPI 不是准确率，而是「用户是否愿意滑到最后一张」。**

## 三、产品原则（五条，作为需求准入闸门）

| 编号 | 原则 | 含义 | 违反示例 |
|---|---|---|---|
| **P1** | **决策越少越好** | 主链路决策点 ≤ 5 个；新功能默认进二级页面 | 创建流程加「分类选择」「编辑滤镜」 |
| **P2** | **等待必须被看见** | 任何超过 1 秒的等待都必须转化为有信息量的内容，禁止孤立 Loading | 出片时转圈等待 |
| **P3** | **措辞塑造价值** | 全链路使用「留下 / 放下」，不用「喜欢 / 不喜欢」「保留 / 删除」 | 「删除这张照片？」确认弹窗 |
| **P4** | **分享物是一等公民** | 任何功能不得损害最终分享物的完成度与美感 | 满屏品牌水印、强制片头 |
| **P5** | **峰值即转化** | 商业入口嵌在情绪峰值处，不做独立商城 Tab | 底部导航加「商城」 |

> 新增需求评审流程：先问「违反哪条原则」→ 若违反，需明确说明为何收益大于代价，并由项目负责人拍板。

## 四、情绪地图（六段，每段对应明确设计手段）

| 环节 | 目标情绪 | 设计手段 | 必须避免 |
|---|---|---|---|
| **打开首页** | 期待 | 未完成的任务置顶并以进度吸引续做；空状态直接引导「选 20 张最近的照片试试」 | 空列表、纯功能入口罗列 |
| **创建任务** | 轻松 | 先选照片、名称自动生成（如「八月·海边」）；默认参数已可用 | 表单填写、强制命名 |
| **出片转场** | **惊喜（峰值 1）** | 打印 → 落堆 → 顶卡放大；物理隐喻（厚度、阴影、遮挡关系）；首批就绪即可开始 | 进度条 / 转圈 |
| **滑卡筛选** | 心流 | 跟手手势、即时视觉反馈、剩余张数暗示、可撤销 | 掉帧、一次给 300 张、误操作不可回退 |
| **选片完成** | 成就 | 「你留下了 15 张」+ 处理总量 / 耗时统计 | 干巴巴的「完成」 |
| **生成作品集** | **感动（峰值 2）** | 音乐 + 转场节奏 + 首帧标题卡；情感峰值的顶点 | 生硬切换、等待无反馈 |
| **分享** | 认同 | 高质量成品、极小品牌露出、数据型钩子文案 | 水印遮挡照片 |

**两个峰值的分工**：峰值 1（出片）负责让用户觉得「这个 App 有意思」，峰值 2（作品集）负责让用户觉得「这些照片有价值」。**打印转化只发生在峰值 2**。

## 五、成功指标

### 5.1 北极星指标

**周完成作品集生成的用户数**（Weekly Completed Portfolio Users）
—— 它同时反映了激活、筛选完成率与生成成功率，是产品价值的最终交付点。

### 5.2 漏斗与过程指标

| 环节 | 指标 | 目标（初期参考） |
|---|---|---|
| 创建 → 完成选片 | 选片完成率 | ≥ 60% |
| 单次选片 | 平均处理张数 | 40–80 张 |
| 完成选片 → 生成 | 生成转化率 | ≥ 80% |
| 生成 → 分享 | 分享率 | ≥ 40% |
| 分享 → 新用户激活 | K 因子 | ≥ 0.3 |
| 生成 → 打印下单 | **打印转化率** | 3–8%（成册类目参考区间） |

### 5.3 体验指标（硬指标，不达标即视为未完成）

- 出片动画：稳定 ≥ 55 fps，中端机型不得掉到 45 fps 以下
- 滑卡跟手：触摸位移到响应的延迟 < 50 ms
- 冷启动到首页可交互：< 1.5 s
- 作品集生成耗时：< 8 s（超过 3 s 必须有 P2 式过程可视化）

## 六、明确不做的事（一期）

| 不做 | 原因 |
|---|---|
| 图片编辑（滤镜、裁剪、调色） | 违反 P1；成熟竞品已充分覆盖；与「精选」的核心价值无关 |
| 社区、关注、评论、点赞 | 违反 P4；运营成本高；分享发生在微信，不发生在 App 内 |
| 云存储与多端同步 | 一期非核心，成本高 |
| AI 修图 / AI 生成 | 与「真实照片」的情感定位冲突 |
| 独立的商城 / 购物车 | 违反 P5 |

## 七、决策记录（2026-09-04 更新）

### 7.1 已拍板

| 编号 | 议题 | 决策 | 依据 |
|---|---|---|---|
| **D1** | MVP 一期范围 | **完整版：选片 + 长图 + 视频**（视频含失败降级至长图） | 视频是扩散主力，闭环必须完整 |
| **D2** | 滑卡分批与上限 | **单次 60 张**，滑完可继续下一批，支持中断续做 | 平衡心流时长与疲劳控制 |
| **D3** | 音乐版权 | **内置 3–5 首自制/免版税曲库**，一期不支持本地音乐 | 规避合规风险 |
| **D4** | 品牌露出强度 | **采用样稿方案**：视频尾帧 1.5s + 长图 1.5% 高度 | P4；一旦被识别为广告，扩散率先于品牌收益崩塌 |
| **D5** | 打印业务深度 | **一期只放钩子**：预约 / 心愿登记，不接支付 | 需求未验证前零供应链投入 |
| **D6** | 筛选机制 | **一票否决**（左滑放下 / 右滑留下），不做打分制 | 打分制增加决策负担，违反 P1 |

### 7.2 默认采用（未显式确认，如需推翻请提出）

| 编号 | 议题 | 默认值 | 理由 |
|---|---|---|---|
| **D7** | 分享物可编辑性 | **一期不可编辑**（不改文案、不换音乐） | 个性感的收益小于决策点与开发量的代价 |
| **D8** | 长图与印刷稿版式 | **严格一致**（同一套设计资产） | 这是打印转化的核心机制，不一致则该机制失效 |
| **D9** | 视频生成失败降级 | **自动降级为长图**，同等仪式感呈现 | 禁止只弹「生成失败」，否则直接摧毁刚建立的情绪峰值 |

### 7.3 仍待确认

| 编号 | 议题 | 阻塞对象 |
|---|---|---|
| **D10** | 目标 API 版本 / 最低支持机型 | 阶段 5 技术验证（部分动效与媒体能力有版本门槛） |
| **D11** | 是否有鸿蒙真机（HarmonyOS NEXT） | 动效性能验证 —— **8GB 内存下模拟器不可行，真机是必需品** |
| **D12** | 真实照片素材 | 出片间隔、卡片停留时长等动效参数调优 |

### 7.4 D1 决策带来的连带要求

一期包含视频合成，因此以下三项从「建议」升级为「必须」：

1. 视频合成成功率 ≥ 99%，**必须实现 D9 降级路径**；
2. 视频合成的内存峰值必须在**最低支持机型**上实测（开发机内存不足不构成豁免理由）；
3. 阶段 5 技术验证必须包含「视频合成」这一项，风险等级最高。
